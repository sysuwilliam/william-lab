# RA4M2-SENSOR 使用 DAPLink 在 VS Code 中调试补充指南

本文补充说明在 `RA4M2-SENSOR` 开发板没有板载 J-Link 的情况下，如何使用 `DAPLink + pyOCD + Cortex-Debug` 在 VS Code 中完成下载和调试。

官方 VS Code 插件默认生成的调试配置偏向 `SEGGER J-Link`，而 DAPLink 需要通过 `pyOCD` 先启动一个 GDB Server，再由 VS Code 连接到该 GDB Server。

参考资料：

- Renesas VS Code RA 快速开始文档：<https://tool-support.renesas.com/e2studio/vscode/docs/quick-start-ra.html>
- Renesas VS Code 创建和构建工程文档：<https://tool-support.renesas.com/e2studio/vscode/docs/creating-and-building-project.html>
- pyOCD GDB Server 文档：<https://pyocd.io/docs/gdbserver.html>
- pyOCD Target Support 文档：<https://pyocd.io/docs/target_support.html>

## 1. 硬件和工程信息

本次使用的开发板和芯片为：

```text
开发板：RA4M2-SENSOR
MCU：R7FA4M2AD3CFL#AA0
FSP Device：R7FA4M2AD3CFL
内核：Arm Cortex-M33
封装：LQFP-48
```

在 FSP Smart Configurator 新建工程时，芯片应选择：

```text
RA4
-> RA4M2
-> RA4M2 - 48 Pin
-> R7FA4M2AD3CFL
```

工程类型选择：

```text
Flat (Non-TrustZone) Project
```

RTOS 选择：

```text
No RTOS
```

模板选择：

```text
Bare Metal - Minimal
```

说明：当前版本的 RA pack 中可能没有直接显示 `Blinky` 模板，选择 `Bare Metal - Minimal` 后手动添加 LED 闪烁代码即可。

## 2. DAPLink 接线

DAPLink 通过 SWD 接口连接 RA4M2-SENSOR：

```text
DAPLink        RA4M2-SENSOR
SWDIO      ->  SWDIO
SWCLK      ->  SWCLK
GND        ->  GND
VTref/3V3  ->  3.3V
RESET      ->  RESET，可选但建议连接
```

注意：

- `VTref` 通常只是给调试器检测目标板电压，不一定负责给目标板供电。
- RA4M2-SENSOR 工作电压为 3.3V，不要把 5V 直接接到 MCU IO。
- 如果 DAPLink 不能识别目标板，先检查 GND、VTref、SWDIO、SWCLK 是否接反。

## 3. 安装 VS Code 扩展

需要安装以下 VS Code 扩展：

```text
Renesas Platform
Cortex-Debug
```

`Renesas Platform` 用于创建、配置和构建 RA 工程；`Cortex-Debug` 用于连接 pyOCD 的 GDB Server。

## 4. 安装 pyOCD

在 VS Code 终端或 PowerShell 中执行：

```powershell
pip install -U pyocd
```

安装完成后检查版本：

```powershell
pyocd --version
```

如果系统提示找不到 `pyocd`，需要确认 Python 的 Scripts 目录已经加入系统 `PATH`。

## 5. 添加 RA 芯片支持 pack

pyOCD 默认可能不认识 `r7fa4m2ad`，因此需要添加 Renesas RA DFP pack。

在工程根目录创建 `packs` 文件夹：

```powershell
cd D:\Programming\TEST
mkdir packs
```

将 `Renesas.RA_DFP.6.4.0.pack` 放入：

```text
D:\Programming\TEST\packs\Renesas.RA_DFP.6.4.0.pack
```

然后在工程根目录创建 `pyocd.yaml`：

```yaml
pack:
  - ./packs/Renesas.RA_DFP.6.4.0.pack
```

如果 pack 文件放在其他目录，也可以修改 `pyocd.yaml` 中的路径。例如：

```yaml
pack:
  - D:/Renesas/Renesas.RA_DFP.6.4.0.pack
```

路径建议使用 `/`，避免 Windows 反斜杠转义问题。

## 6. 配置用户 LED 引脚

打开图形化配置界面：

```text
右键 configuration.xml
-> Open With...
-> RA Smart Configurator
```

进入底部 `Pins` 页面后，配置 `P103` 和 `P104`：

```text
P103 -> GPIO -> Output mode
P104 -> GPIO -> Output mode
```

RA4M2-SENSOR 原理图中，用户 LED 连接到 `P102`、`P103`、`P104`，其中本例使用：

```text
P103
P104
```

LED 为高电平点亮，因此可以设置初始状态为：

```text
Output mode (Initial Low)
```

配置完成后点击右上角：

```text
Generate Project Content
```

生成后会更新 `ra_gen/pin_data.c`、`ra_cfg/fsp_cfg/bsp/bsp_pin_cfg.h` 等配置文件。

## 7. 添加 LED 测试代码

打开：

```text
src/hal_entry.c
```

在 `hal_entry()` 中添加 LED 闪烁逻辑。示例代码如下：

```c
#include "hal_data.h"

void hal_entry(void)
{
    R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_03, BSP_IO_LEVEL_LOW);
    R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_04, BSP_IO_LEVEL_LOW);

    while (1)
    {
        R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_03, BSP_IO_LEVEL_HIGH);
        R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_04, BSP_IO_LEVEL_LOW);
        R_BSP_SoftwareDelay(100, BSP_DELAY_UNITS_MILLISECONDS);

        R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_03, BSP_IO_LEVEL_LOW);
        R_IOPORT_PinWrite(&g_ioport_ctrl, BSP_IO_PORT_01_PIN_04, BSP_IO_LEVEL_HIGH);
        R_BSP_SoftwareDelay(100, BSP_DELAY_UNITS_MILLISECONDS);
    }
}
```

如果使用的是 FSP 生成的默认模板，文件中可能还有 TrustZone 或多核相关的条件编译代码。可以保留这些代码，只要保证 LED 闪烁逻辑位于 `hal_entry()` 中即可。

## 8. 配置 launch.json

官方生成的 `launch.json` 中通常默认使用 J-Link：

```json
{
  "type": "renesas-hardware",
  "request": "launch",
  "name": "Renesas GDB Debugging",
  "target": {
    "device": "R7FA4M2AD",
    "debuggerType": "SEGGERJLINKARM",
    "deviceFamily": "RA"
  }
}
```

由于本次使用 DAPLink，需要在 `.vscode/launch.json` 中新增 `DAPLink / pyOCD` 配置：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "renesas-hardware",
      "request": "launch",
      "name": "Renesas GDB Debugging",
      "target": {
        "device": "R7FA4M2AD",
        "debuggerType": "SEGGERJLINKARM",
        "deviceFamily": "RA"
      }
    },
    {
      "name": "DAPLink / pyOCD",
      "type": "cortex-debug",
      "request": "launch",
      "cwd": "${workspaceFolder}",
      "executable": "${workspaceFolder}/build/Debug/TEST.elf",
      "servertype": "external",
      "gdbTarget": "localhost:3333",
      "runToEntryPoint": "main",
      "targetId": "r7fa4m2ad",
      "armToolchainPath": "C:/Users/18527/.renesas/platform/arm-gnu/13.3.Rel1/arm-gnu-toolchain-13.3.rel1-mingw-w64-i686-arm-none-eabi/bin",
      "gdbPath": "C:/Users/18527/.renesas/platform/arm-gnu/13.3.Rel1/arm-gnu-toolchain-13.3.rel1-mingw-w64-i686-arm-none-eabi/bin/arm-none-eabi-gdb.exe"
    }
  ]
}
```

需要根据自己的工程名修改：

```json
"executable": "${workspaceFolder}/build/Debug/TEST.elf"
```

如果工程名是 `RA4M2_Blinky`，则可能需要改为：

```json
"executable": "${workspaceFolder}/build/Debug/RA4M2_Blinky.elf"
```

`armToolchainPath` 和 `gdbPath` 也要改成本机实际安装路径。

## 9. 配置 settings.json

为了让 CMake 调试按钮也使用 DAPLink，可以修改 `.vscode/settings.json` 中的 `cmake.debugConfig`：

```json
{
  "cmake.configureOnOpen": true,
  "cmake.configureOnEdit": true,
  "cmake.useCMakePresets": "never",
  "cmake.options.statusBarVisibility": "visible",
  "cmake.sourceDirectory": "${workspaceFolder}",
  "cmake.buildDirectory": "${workspaceFolder}/build/${buildType}",
  "cmake.preferredGenerators": [
    "Ninja",
    "MinGW Makefiles",
    "Unix Makefiles"
  ],
  "cmake.debugConfig": {
    "name": "DAPLink / pyOCD",
    "type": "cortex-debug",
    "request": "launch",
    "cwd": "${workspaceFolder}",
    "executable": "${workspaceFolder}/build/Debug/TEST.elf",
    "servertype": "external",
    "gdbTarget": "localhost:3333",
    "runToEntryPoint": "main",
    "targetId": "r7fa4m2ad",
    "armToolchainPath": "C:/Users/18527/.renesas/platform/arm-gnu/13.3.Rel1/arm-gnu-toolchain-13.3.rel1-mingw-w64-i686-arm-none-eabi/bin",
    "gdbPath": "C:/Users/18527/.renesas/platform/arm-gnu/13.3.Rel1/arm-gnu-toolchain-13.3.rel1-mingw-w64-i686-arm-none-eabi/bin/arm-none-eabi-gdb.exe"
  },
  "clangd.arguments": [
    "--query-driver=${env:ARM_GCC_TOOLCHAIN_PATH}*",
    "--compile-commands-dir=${workspaceFolder}",
    "--background-index"
  ],
  "cmake.copyCompileCommands": "${workspaceFolder}/compile_commands.json"
}
```

## 10. 编译工程

在 VS Code 底部确认 CMake 工具链为：

```text
Renesas Platform: ARM GNU Toolchain
```

然后点击底部：

```text
生成 [all]
```

或使用命令面板：

```text
Ctrl + Shift + P
-> CMake: Build
```

编译成功时会看到类似输出：

```text
生成已完成，退出代码为 0
```

并生成：

```text
D:\Programming\TEST\build\Debug\TEST.elf
```

## 11. 启动 pyOCD GDB Server

DAPLink 调试前，必须先手动启动 pyOCD 后端。

在 VS Code 终端或 PowerShell 中执行：

```powershell
cd D:\Programming\TEST
pyocd gdbserver --target r7fa4m2ad
```

成功后终端会保持运行，并监听：

```text
localhost:3333
```

此终端不能关闭。关闭后，VS Code 调试会连接失败。

如果出现以下错误：

```text
Target type r7fa4m2ad not recognized.
```

说明 pyOCD 没有加载 RA DFP pack。检查：

```text
D:\Programming\TEST\pyocd.yaml
D:\Programming\TEST\packs\Renesas.RA_DFP.6.4.0.pack
```

如果出现以下错误：

```text
Failed to launch GDB: localhost:3333: Connection timed out
```

说明 VS Code 启动调试时，`pyocd gdbserver` 还没有运行，或者端口不是 `3333`。

## 12. 启动 VS Code 调试

确保 `pyocd gdbserver` 正在运行后，在 VS Code 左侧调试面板选择：

```text
DAPLink / pyOCD
```

然后按：

```text
F5
```

如果连接成功，程序会下载到芯片，并停在：

```text
main
```

此时可以：

- 设置断点
- 单步执行
- 查看变量
- 查看寄存器
- 继续运行程序

点击继续运行后，板载用户 LED 应交替闪烁。

## 13. 常见问题

### 13.1 VS Code 仍然使用 J-Link

检查左侧调试配置是否选择了：

```text
DAPLink / pyOCD
```

如果选择的是：

```text
Renesas GDB Debugging
```

则仍然会走 J-Link 配置。

### 13.2 Cortex-Debug 连接超时

先运行：

```powershell
pyocd gdbserver --target r7fa4m2ad
```

再按 `F5`。

### 13.3 pyOCD 不认识芯片

确认 `pyocd.yaml` 和 pack 文件路径正确：

```yaml
pack:
  - ./packs/Renesas.RA_DFP.6.4.0.pack
```

可以执行：

```powershell
pyocd list --targets
```

查看是否已经出现 RA 相关目标。

### 13.4 无法识别 DAPLink

检查：

- DAPLink 是否在设备管理器中正常枚举
- USB 线是否支持数据传输
- SWDIO / SWCLK / GND / VTref 是否接好
- 目标板是否已经上电

### 13.5 LED 不闪烁

检查：

- `P103`、`P104` 是否已在 FSP 图形界面中配置为 `GPIO Output`
- 是否点击过 `Generate Project Content`
- 是否重新编译并重新下载程序
- 程序是否停在断点处没有继续运行

## 14. 完整调试流程总结

完整流程可以概括为：

```text
1. VS Code 安装 Renesas Platform 和 Cortex-Debug
2. Renesas Quick Install 安装 RA 工具链和 Smart Configurator
3. 创建 RA4M2 工程，芯片选择 R7FA4M2AD3CFL
4. 打开 configuration.xml，配置 P103/P104 为 GPIO Output
5. Generate Project Content
6. 修改 hal_entry.c，添加 LED 闪烁代码
7. CMake Configure
8. CMake Build，生成 TEST.elf
9. 添加 packs/Renesas.RA_DFP.6.4.0.pack 和 pyocd.yaml
10. 运行 pyocd gdbserver --target r7fa4m2ad
11. VS Code 选择 DAPLink / pyOCD
12. 按 F5 下载并调试
```

这套流程的关键点是：DAPLink 不直接由 Renesas 官方 `renesas-hardware` 调试器配置驱动，而是通过 pyOCD 提供 GDB Server，VS Code 的 Cortex-Debug 再连接到这个 GDB Server。
