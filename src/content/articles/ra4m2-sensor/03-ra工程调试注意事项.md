# RA 工程调试注意事项

本文记录 RA4M2 工程在 VS Code、FSP、DAPLink/pyOCD 调试时容易遇到的问题，以及 LED、Button 工程中已经验证过的处理方式。

## 1. 调试产物名称要和 launch.json 一致

当前 LED 和 Button 工程虽然目录名不同，但 CMake 工程名都是 `GPIO`，实际生成的调试文件是：

```text
build/Debug/GPIO.elf
```

如果 `.vscode/launch.json` 中写成 `LED.elf`、`Button.elf` 或 `TEST.elf`，调试时会报找不到可执行文件。应改为：

```json
"executable": "${workspaceFolder}/build/Debug/GPIO.elf"
```

`.vscode/settings.json` 里的 `cmake.debugConfig.executable` 也建议同步改成同样路径，避免从 CMake 面板启动调试时使用旧配置。

## 2. DAPLink/pyOCD 调试服务器要先启动

`launch.json` 使用：

```json
"servertype": "external"
```

这表示 Cortex-Debug 不会自动启动 pyOCD，只会连接已经存在的 GDB Server。因此调试前需要先在终端中运行：

```powershell
pyocd gdbserver --target r7fa4m2ad
```

看到下面信息后，再点击 VS Code 的调试按钮：

```text
GDB server listening on port 3333
```

如果出现 `Remote communication error` 或 `Target disconnected`，先确认 pyOCD 终端没有退出，且 3333 端口没有被旧进程占用。

## 3. gdbTarget 建议使用 127.0.0.1

在 Windows 上，`localhost` 有时会因为解析到 IPv6 或旧连接而导致 GDB 连接异常。建议使用明确的 IPv4 地址：

```json
"gdbTarget": "127.0.0.1:3333"
```

## 4. LED 引脚与电平极性

本板上当前验证可用的三个 LED 引脚为：

```text
LED1: P002
LED2: P103
LED3: P104
```

FSP Pins 中也应将它们配置为 GPIO Output。代码中对应：

```c
BSP_IO_PORT_00_PIN_02
BSP_IO_PORT_01_PIN_03
BSP_IO_PORT_01_PIN_04
```

本板 LED 为高电平亮、低电平灭，因此宏应按下面语义定义：

```c
LED_ON  -> BSP_IO_LEVEL_HIGH
LED_OFF -> BSP_IO_LEVEL_LOW
```

不要直接沿用低电平点亮的示例注释，否则现象会反过来。

## 5. 初始化 IOPORT

如果 `ra_gen/main.c` 没有在进入 `hal_entry()` 前调用 `g_hal_init()`，用户代码中使用 `R_IOPORT_PinWrite()`、`R_IOPORT_PinRead()` 前应确保已经打开 IOPORT。

可以在 `LED_Init()` 中调用：

```c
R_IOPORT_Open(&g_ioport_ctrl, &g_bsp_pin_cfg);
```

并显式配置 LED 引脚为输出低电平，作为默认灭灯状态。

## 6. Button 工程按键消抖

Button 工程中按键扫描逻辑采用：

1. 第一次读取按键电平。
2. 检测到按下后延时 20 ms。
3. 再次读取确认。
4. 等待按键松开后返回 `KEY_ON`。

这种方式可以避免一次按下触发多次 LED 翻转。目前实测没有明显抖动。

## 7. 判断问题位置的顺序

如果 LED 不亮，建议按下面顺序排查：

1. 确认程序是否已经运行到 `hal_entry()` 或 `R_BSP_SoftwareDelay()`。
2. 确认 `launch.json` 使用的是实际生成的 `GPIO.elf`。
3. 确认 pyOCD 已启动并监听 `127.0.0.1:3333`。
4. 确认 LED 引脚是否是 `P002/P103/P104`。
5. 固定输出高电平测试 LED 是否点亮。
6. 如果固定高电平亮，说明 LED 是高电平有效，再恢复闪烁逻辑。

这个顺序可以避免把调试连接问题、引脚配置问题和电平极性问题混在一起。
